# Harden password reset

## Description
Serves US-5 (UI/UX). Closes three gaps left by forgot password (US-5-T-9): sessions signed in before a password change stay valid for up to 7 days, the reset endpoints have no rate limit, and emails are case-sensitive, so `Ada@x.com` and `ada@x.com` are different accounts. Issue #98.

## Specs
- Resetting or changing the password signs out every session that was signed in before it.
- Changing the password in Settings keeps the current session signed in (AuthService answers with a fresh token).
- A signed-out session gets 401 from `GET /me`, so the frontend sends the player back to log in.
- `POST /password/forgot` and `POST /password/reset` answer 429 after too many requests from one IP (5 per 15 minutes).
- `POST /password/forgot` sends at most 3 reset emails an hour to one address. Past that it answers the same 200, but sends nothing.
- Sign-up, log-in and forgot password treat emails without regard to case or surrounding spaces. Emails are stored in lowercase.

## Requirements
- The AuthService changes live in `service/AuthService/src/service.ts`, `src/middleware.ts` and `src/app.ts`.
- `users` gets a `password_changed_at` column, and a unique index on `lower(email)`, in `service/AuthService/sql/schema.sql`. Creating them in Cloud SQL is US-5-T-12.
- A token is signed out when its issued-at time (`iat`, in whole seconds) is before `password_changed_at` rounded down to the second, so the fresh token from a password change is not signed out by its own change.
- `changePassword` in `frontend/app/login/controller.tsx` stores the fresh token. Frontend tests (`frontend/test/`) stub the network and do not touch backend services.
- The rate limit is kept in memory. No new dependencies.
- AuthService tests (`service/AuthService/test/`) fake the mailer and use fake timers for the rate limit.
- GameService and LobbyService do not check `password_changed_at`. An older session is signed out on its next `GET /me`.

## Acceptance criteria
1. After a password reset, a token issued before it gets 401 from `GET /me`.
2. After a password change, a token issued before it gets 401 from `GET /me`, and the token returned by the change works, so the Settings page stays signed in.
3. A sixth `POST /password/forgot` or `POST /password/reset` from one IP within 15 minutes answers 429, and requests work again after the window.
4. A fourth reset request for one address within an hour sends no email, and still answers 200.
5. Signing up as `Ada@X.com` and logging in as ` ada@x.com ` works.
6. Signing up as `ada@x.com` after `Ada@x.com` exists answers 409.
7. Forgot password for `ADA@x.com` sends the email to the `ada@x.com` account.
