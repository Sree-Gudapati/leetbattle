# Show Victory or Defeat and the final scores on the match result screen

## Description
Serves US-6 (In-Game, #67). When a match ends, the game page's result screen says which team won ("Team 2 wins" or "Draw"), why the match ended, and links back to the lobby (US-6-T-2). It does not tell the player whether *they* won, and it does not show the final score. This task adds both to the result screen: a "Victory" or "Defeat" line for the viewing player, and the final score of each team.

Out of scope: the separate `/results` page (US-4-T-5), the in-match scoreboard (US-4-T-4), how points are scored (US-6-T-9), per-player statistics, rematch, and any change to GameService or to the `game:ended` payload.

## Specs
- The result screen is `ResultScreen` in `frontend/app/game/[gameId]/page.tsx`. It is shown once the game socket (`frontend/app/game/socket-context.tsx`, `useGameSocket`) receives `game:ended` with `{ winner: 'a' | 'b' | null, reason }`.
- The viewer's team is the `team` of the entry in the last `game:state`'s `players` whose `userId` equals the signed-in user's `id` (`useAuth` from `frontend/app/login/context`).
- Victory / Defeat line, shown on the result screen:
  - `winner` is the viewer's team: the text "Victory" is shown and "Defeat" is not.
  - `winner` is the other team: the text "Defeat" is shown and "Victory" is not.
  - `winner` is `null` (draw): neither "Victory" nor "Defeat" is shown.
  - The signed-in user is not in `players`: neither "Victory" nor "Defeat" is shown.
- Final scores, shown on the result screen:
  - A list with the accessible name "Final scores" (`role="list"`, `aria-label="Final scores"`) holds exactly two items, Team 1 first, then Team 2.
  - Each item's text is the team name followed by that team's score from the last `game:state`'s `scores`, e.g. `Team 1 450` and `Team 2 300`.
  - A score of 0 is shown as `0`, not left blank.
- Unchanged: the heading ("Team 1 wins", "Team 2 wins" or "Draw"), the line explaining why the match ended, and the "Back to lobby" link.

## Requirements
- Frontend only. No change to GameService, to the `game:ended` or `game:state` payloads, or to `socket-context.tsx`'s public API.
- Read the viewer and the scores from the existing `useAuth` and `useGameSocket`. Do not add a second socket client or a new request.
- Team names come from the existing `TEAMS` list in `page.tsx` ("Team 1" for `a`, "Team 2" for `b`).
- Colours use the theme tokens from `docs/frontend/theming.md`; no hard-coded colours.
- No new runtime dependencies.
- Frontend tests mock the game socket and never call a real backend service.
- The existing US-6-T-2 result screen tests in `frontend/test/game.test.tsx` keep passing unchanged.

## Acceptance criteria
1. When the viewer's team wins, the result screen shows "Victory" and not "Defeat".
2. When the other team wins, the result screen shows "Defeat" and not "Victory".
3. When the match is a draw, the result screen shows neither "Victory" nor "Defeat".
4. When the signed-in user is not one of the match's players, the result screen shows neither "Victory" nor "Defeat".
5. The "Final scores" list shows `Team 1` with team a's final score and `Team 2` with team b's final score, in that order.
6. A team that finished on 0 points is shown with `0` in the "Final scores" list.
7. The heading, the end reason line and the "Back to lobby" link are still shown.
