# Create the password reset tables in Cloud SQL

## Description
Serves US-5 (UI/UX). Forgot password (PR #94) stores reset links in a new `password_resets` table, and hardening (US-5-T-13) adds a column and an index to `users`. These are in `service/AuthService/sql/schema.sql` but must be created by hand in the deployed auth database, or `POST /password/forgot` and `POST /password/reset` fail when deployed. The Brevo settings from US-5-T-11 also need to reach the deployed AuthService. Issue #97. Related: #60 (GCP setup).

## Specs
- The deployed `auth_service` database has the `password_resets` table from `schema.sql`.
- The deployed `users` table has the `password_changed_at` column and the `users_email_lower` unique index from US-5-T-13.
- The deployed AuthService has `BREVO_API_KEY` and `MAIL_FROM` set.

## Requirements
- Only run the statements from `service/AuthService/sql/schema.sql` (they are all `IF NOT EXISTS`, so running them twice is safe).
- Before creating `users_email_lower`, check that no two deployed accounts have emails that differ only by case.
- Keep `BREVO_API_KEY` out of the repository (Secret Manager or the Cloud Run service's settings).
- No code changes.

## Acceptance criteria
1. On the deployed site, "Forgot password?" sends a reset email.
2. The emailed link changes the password, and the new password logs in.
3. `password_resets`, `users.password_changed_at` and `users_email_lower` exist in the deployed database.
