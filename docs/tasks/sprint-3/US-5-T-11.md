# Send the password reset email

## Description
Serves US-5 (UI/UX). Forgot password (US-5-T-9, PR #94) writes the reset link to the AuthService log instead of emailing it. This task sends the link to the player's inbox through Brevo, so a player can reset their password without help. Issue #96. Finishing this finishes #84.

## Specs
- `POST /password/forgot` for an email with an account sends that address an email from LeetBattle.
- The email contains the reset link (`<frontend>/login/reset?token=...`) and says the link works for 30 minutes.
- The email is sent through Brevo's HTTP API (`POST https://api.brevo.com/v3/smtp/email`) with the `BREVO_API_KEY` key, from the `MAIL_FROM` address.
- When Brevo refuses the email, the mailer throws. `POST /password/forgot` still answers the same way (see US-5-T-9).
- When `BREVO_API_KEY` is not set (local development), the link is written to the service log as before.
- When `BREVO_API_KEY` is set, the link is never written to the log.

## Requirements
- Sending lives in `service/AuthService/src/utils/mailer.ts` (`sendPasswordReset`). Nothing else changes in `service.ts`.
- Uses Node 20's built-in `fetch`. No new dependencies.
- `BREVO_API_KEY` and `MAIL_FROM` are read from the environment (root `.env` locally, the Cloud Run service when deployed).
- AuthService tests (`service/AuthService/test/`) fake `fetch` and never call Brevo.

## Acceptance criteria
1. With a key set, `sendPasswordReset` posts to Brevo's send endpoint with the `api-key` header.
2. The email goes to the account's address, from `MAIL_FROM`.
3. The email body contains the reset link and the 30-minute expiry.
4. A non-2xx answer from Brevo makes `sendPasswordReset` throw.
5. Without a key, the link is logged and nothing is sent.
6. With a key, the link is not logged.
